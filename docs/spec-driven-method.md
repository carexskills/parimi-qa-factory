# Spec-driven development in this repo

| step | where it lives in this repo | who writes it | who approves it |
| --- | --- | --- | --- |
| constitution | `docs/working-agreement.md`, `AGENTS.md` | Human | Human |
| specify | `tickets/`, `business-rules/` | Human | Human |
| clarify | not yet; suggest `specs/clarifications/` | Human | Human |
| plan | `specs/plans/` | Planner agent | Human |
| tasks | not yet; suggest `specs/tasks/` | Codex | Human |

Rules and acceptance criteria anchor every test assertion.
Clarification closes gaps before planning hardens assumptions.
Approved plans become tasks, keeping generated tests traceable.
