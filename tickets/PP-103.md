# PP-103 — Spaces-only booking reason does not default to General visit

- **Title:** Spaces-only booking reason is not shown as General visit
- **Description:** A booking submitted with a reason containing only spaces did not display the required “General visit” reason in the resulting appointment. This is a suspected product defect against BR-BOOK-06.
- **Preconditions / environment:** Signed-in Silver patient session from the saved seed; Chromium Playwright run. The test selected Daniel Okafor and a future open slot.
- **Steps to reproduce:**
  1. Open Find care and start a booking with Daniel Okafor.
  2. Choose an in-person visit and a future open slot.
  3. Enter three spaces in Reason for visit.
  4. Confirm the booking and finish the booking flow.
  5. Inspect the appointment for the selected slot.
- **Expected result:** Under BR-BOOK-06, a reason containing only spaces counts as empty, so the appointment reason is “General visit”.
- **Actual result:** The appointment row for Tue, Dec 1, 10:30 AM did not contain the exact text “General visit”; the expected reason locator timed out.
- **Business rule / BR-ID:** BR-BOOK-06 — Booking reason.
- **Evidence:** `tests/booking/reason.spec.ts` BR-BOOK-06-B; Playwright error context `test-results/booking-reason-Booking-a-v-1b015-n-defaults-to-General-visit-chromium/error-context.md`; screenshot `test-results/booking-reason-Booking-a-v-1b015-n-defaults-to-General-visit-chromium/test-failed-1.png`; trace `test-results/booking-reason-Booking-a-v-1b015-n-defaults-to-General-visit-chromium/trace.zip`.
- **Impact and risk:** Not scored.
- **Approvals:** Pending; no approval tier assigned because impact and likelihood scores were not supplied.
- **Open questions:** Does the application store a blank reason, or is the fallback missing only from the appointment display?
